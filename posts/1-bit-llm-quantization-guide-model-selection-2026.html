手机跑 27B 大模型？1-bit 量化落地指南与模型选型 2026

AI开发平台 2026-07-18 · 32 分钟

当一个 27B 模型只要 3.9GB

先看一个数字。一个 270 亿参数的大模型，用传统 FP16 精度存储需要约 54GB 显存——这是一张 A100 都装不下的规模。但在 2026 年 7 月，PrismML 发布的 1-bit 版 Bonsai 27B 只有 3.9GB，能塞进一台 iPhone 17 Pro，以约 11 tokens/s 的速度在手机上跑起来（PrismML 官方公告）。

这不是把模型"缩小"，而是把每个权重从 16 位浮点数压缩到几乎只剩 1 位信息。压缩比高达 10 到 30 倍，CPU 推理能耗最多降低 9 到 12 倍。对于想在手机、笔记本、边缘设备上跑大模型的人来说，1-bit 量化是当前效率提升最激进的一条路。

但"激进"往往意味着"有代价"。1-bit 量化到底是怎么做到的？它会损失多少性能？哪些模型能用、用哪个框架跑、适合什么场景？这篇文章把这些问题一次讲清楚，帮你在真实项目里做出选型决策。

说明：本文数据来自各厂商公开发布、arXiv 论文与模型卡，引用内容均经改写以符合授权合规要求，关键数字建议以官方来源为准。

一、先搞懂：什么是 1-bit / 1.58-bit 量化

传统大模型的每个权重是一个 16 位或 32 位浮点数，能表示极其丰富的数值。量化的本质，就是用更少的比特去近似这些数值，换取更小的体积和更快的计算。

4-bit 量化（如 GPTQ、AWQ）已经能把模型压到原来的四分之一，是目前最主流的方案。而 1-bit 量化把这件事推到了极限：权重只保留极少数几个离散值。

这里有两个容易混淆的概念，务必分清：

  • 1-bit（binary，二值）：权重只有两个值 {-1, +1}。理论上每权重 1 比特，实际因为需要分组缩放系数，约 1.125 比特。
  • 1.58-bit（ternary，三值）：权重有三个值 {-1, 0, +1}。因为 log₂(3) ≈ 1.58，所以叫 1.58-bit。多出来的那个 0 允许模型"关闭"某些连接，表达能力明显更强。

微软在 2024 年那篇奠基性论文《The Era of 1-bit LLMs》里提出的核心观点是：当权重被约束到 {-1, 0, +1} 时，矩阵乘法里最昂贵的乘法运算几乎全部退化成了加减法（arXiv:2402.17764）。这不只是省内存，更是省电、省时钟周期，甚至为专用硬件打开了一扇新门。

为什么这么极端的压缩还能work？直觉上，大模型有巨大的冗余，真正携带信息的是权重之间的"相对关系"和整体的统计分布，而非每个权重的精确数值。当模型足够大、训练方式得当时，把数值离散到三个档位，损失的信息可以被规模和训练弥补。

二、两大技术路线：原生训练 vs 后训练量化

1-bit 量化有两条根本不同的路线，理解它们的区别是选型的第一步。

路线一：原生量化训练（Native QAT）

从头开始就用低比特约束训练模型。代表方法是微软的 BitLinear 层——它在训练过程中就把权重约束为 ternary，让模型在训练时"学会"适应这种极端离散化。

  • 优点：性能损失小，因为模型天生就是为 1-bit 设计的；定义了全新的 scaling law（性能-成本曲线）。
  • 缺点：必须从头训练，成本高，无法直接复用现有的开源模型。
  • 典型代表：BitNet b1.58、Falcon3 1.58bit。

路线二：后训练量化（PTQ）

拿一个已经训练好的 FP16 模型，事后把它压缩到低比特。

  • 优点：快速、灵活，能直接适配任何现有开源模型（DeepSeek、Qwen、Llama 都行）。
  • 缺点：需要高质量的校准数据，且极限压缩时性能损失比原生训练大。
  • 典型代表：Bonsai 27B、Unsloth Dynamic GGUF、腾讯 Hy-MT。

两条路线的对比可以概括为：

维度 原生训练 (QAT) 后训练量化 (PTQ)
训练方式 从头训练 基于已有模型
成本 高 低
性能保留 接近同尺寸 FP16 90–95%（视方法而定）
灵活性 低（需专门训练） 高（适配任意模型）
代表 BitNet、Falcon3 Bonsai、Unsloth、Hy-MT

一句话概括路线选择：如果你要从零构建一个专为边缘设计的模型，走原生训练；如果你想把现有的强大开源模型塞进小设备，走后训练量化。

三、模型盘点：2024–2026 的关键玩家

原生 1.58-bit 模型

BitNet b1.58 2B4T（微软，2025.4）

这是里程碑式的模型——第一个大规模开源的原生 1-bit LLM，每个参数都是 ternary，在 4 万亿 token 上训练。体积仅 0.4GB，但性能可以匹配同尺寸的全精度开源模型（BitNet b1.58 2B4T 技术报告；模型卡）。它证明了一件事：原生 1-bit 不是理论玩具，而是能达到实用性能的路线。

微软后续还推出了几个重要衍生工作：

  • BitNet a4.8（2024.11）：在 1-bit 权重基础上，把激活值也压到 4-bit，采用混合量化+稀疏策略处理异常值通道，推理时只激活约 55% 的参数，还支持 3-bit KV cache（arXiv:2411.04965）。
  • BitNet v2（2025.4）：引入 H-BitLinear 模块，在激活量化前做在线 Hadamard 变换，把尖锐的激活分布"抹平"成接近高斯的形态，从而实现原生 4-bit 激活而几乎不损失性能（arXiv:2504.18415）。
  • Sparse-BitNet（2025）：发现 1.58-bit 模型天然适配 N:M 半结构化稀疏，结合自定义稀疏张量核，训练和推理可再加速最多 1.30 倍（arXiv:2603.05168）。

Falcon3 / Falcon-Edge 1.58bit 系列（TII）

阿联酋技术创新研究院（TII）基于 BitNet 架构推出的完整系列，覆盖 1B / 3B / 7B / 10B，支持 bitnet.cpp 推理，也支持微调（Falcon-Edge 发布博客）。这是原生路线从"单一模型"走向"完整产品线"的重要补充，让开发者有了不同规模的选择。后续更新的 Falcon-E 系列采用 onebitllm 库 + Axolotl 框架训练（Falcon-E-3B 模型卡）。

高性能 PTQ 模型

Bonsai 27B（PrismML，2026.7）

本文开头那个"塞进手机的 27B 模型"就是它。这是首个能在手机上运行的 27B 级模型，有两个版本：

  • 1-bit 版：binary {-1,+1} 权重 + group-wise scaling（每 128 个权重一个缩放系数），有效比特约 1.125，体积 3.9GB，是"极限压缩"档位，能塞进 iPhone 17 Pro（PrismML: The First 27B-Class Model to Run on a Phone）。
  • Ternary 版：三值权重 + FP16 group-wise scaling，体积 5.9GB，保留约 95% 性能，是"性能优先"档位。

值得注意的是它是多模态模型：约 24.8B 权重的语言组件 + 独立的 4-bit HQQ 视觉塔（0.46B），还附带 DSpark 自推测解码层，在 CUDA 服务路径上带来 1.37 倍无损解码加速（Bonsai-27B-mlx-1bit 模型卡）。关于自推测解码的原理，可以参考我们之前写的DSpark vs DFlash 推测解码对比。

Unsloth Dynamic GGUF（DeepSeek R1 / V3.1 / V4、GLM-5.2 全家桶）

如果说 Bonsai 是"专门压出来的模型"，Unsloth 的动态量化就是"最实用的通用压缩工具"。它的核心创新是智能逐层动态量化——不是把所有层压到同一比特，而是对每一层单独判断：敏感层保留高精度，非敏感的专家层压到 1-bit（Unsloth Dynamic v2.0 GGUFs）。这套方法在一系列超大 MoE 模型上被反复验证：

  • DeepSeek 系列（R1 / V3.1 / V4）：DeepSeek-V3.1 用 TQ1_0 方案（不重要的 MoE 层 1-bit，重要 MoE 层 2-4bit，其余 6-8bit）从 671GB 压到 170GB（减少约 80%），可在单张 24GB 显卡 + 128GB 内存上运行，甚至原生支持 Ollama（Run DeepSeek-V3.1 Locally）。更早的 DeepSeek-R1 Dynamic 1.58bit 在 2×H100（160GB）上可达 140 tokens/s 吞吐（DeepSeek-R1 Dynamic 1.58-bit）。最新的 DeepSeek-V4 系列（V4-Pro 1.6T 参数/49B 激活、V4-Flash 284B 参数/13B 激活，均支持百万 token 上下文）也已提供 UD-IQ1_S 等 1-bit 动态量化档位（DeepSeek-V4-Flash-GGUF）。

  • GLM-5.2（UD-IQ1 / UD-IQ2）：Z.ai 的 744B 级 MoE 旗舰、原生百万 token 上下文。Unsloth 用动态 1-bit / 2-bit 把它从 1.51TB 压到约 217GB（1-bit）/ 239GB（2-bit UD-IQ2_M），让它能在单台 Mac Studio 或高内存工作站上离线运行，消费级硬件上约 3–9 tokens/s（GLM-5.2-GGUF 模型卡；Unsloth compresses GLM-5.2）。

Hy3 IQ1_M（AngelSlim，混合精度 1-bit MoE）

腾讯混元 Hy3 是一个 295B 总参数、21B 激活的超大 MoE 模型（192 个路由专家 top-8 + 1 个共享专家、80 层 + 3.8B MTP 层、256K 上下文）（Tencent-Hunyuan/Hy3 GitHub）。AngelSlim 用 imatrix + 混合 IQ1_M 量化把它压到极致：关键权重保留 Q8_0/Q6_K 高精度，专家层压到 IQ1_M，整体约 1.75 bpw（每权重比特）。据社区实测，即便在这个比特率下，295B 模型仍能输出连贯、语法正确、推理结构清晰的结果，一个 1-bit 构建甚至能塞进一台 MacBook Pro M3 Max 128GB 或单台多卡机器运行（AngelSlim/Hy3-GGUF 实测讨论）。这是"混合精度 + 敏感层保护"策略在超大 MoE 上的典范。

端侧翻译：腾讯 Hy-MT（1.25-bit 落地样本）

除了这些跑在服务器/工作站上的超大模型，1-bit 量化在真正的消费级产品上也已落地。腾讯把 Hy-MT 系列翻译模型（1.8B）用 AngelSlim 1.25-bit 极限量化压缩到 440MB，支持 33 种语言、1056 个翻译方向的完全离线翻译，配合定制的移动端 CPU 内核可在普通手机上流畅运行（Hy-MT2-1.8B-1.25bit-GGUF）。它证明了 1-bit 量化不只是实验室数字，而是能变成用户手机里真正跑得动的产品。

四、量化技术细节：scaling、imatrix 与混合精度

不同模型用的具体技术差异很大，这直接决定了它们的性能和适用场景。

Group-wise scaling（分组缩放）

Bonsai 采用的方案。纯粹把权重压成 {-1,+1} 会损失所有幅度信息，所以它给每 128 个权重配一个 FP16 缩放系数，用这个系数恢复整组权重的大致幅度。这是"端到端全量化"的典型做法——用极少量的高精度参数（缩放系数）保住整体的数值分布。

imatrix + 动态混合精度

Unsloth 和 AngelSlim 采用的方案。核心思想是"不是所有层都一样重要"：

  • 用 importance matrix（imatrix）分析每一层对最终输出的敏感度；
  • 敏感层（如 attention、embedding）保留较高精度；
  • 不敏感层（如深层 MoE 专家）压到 IQ1_M 或更低。

这种"好钢用在刀刃上"的策略，是当前高性能 PTQ 的主流技巧。Hy3 就是典型：关键权重放在 Q8_0/Q6_K，占参数绝大多数的专家层压到 IQ1_M，整体约 1.75 bpw，却能保住 295B 模型的推理能力。GLM-5.2、DeepSeek-V4 的 Unsloth 动态量化也是同一套逻辑。

原生 ternary（无 scale）

BitNet 和 Falcon3 采用。因为是原生训练，模型本身就学会了在 ternary 约束下工作，计算时直接退化为加减法，连缩放系数都不太需要，效率最高。

典型比特数光谱

  • 1.125-bit：纯 binary（Bonsai 1-bit）
  • 1.25-bit：Sherry 的 3:4 细粒度稀疏方案
  • 1.58-bit：标准 ternary（BitNet、Falcon3）
  • 1.71-bit：ternary + scale

一个前沿方向是 sub-1-bit（低于 1 比特）。NanoQuant 用低秩二值分解 + ADMM 优化，首次实现 PTQ 的 sub-1-bit 压缩（arXiv:2602.06694）；SDQ-LLM 借用信号处理里经典的 Sigma-Delta 噪声整形技术，把任意尺寸 LLM 二值化或三值化（arXiv:2510.03275）。这些还处于研究阶段，但预示着压缩的天花板还在往上抬。

五、性能与效率：到底损失多少，省下多少

这是所有人最关心的问题：压这么狠，值吗？

体积

  • Bonsai 27B：约 54GB(FP16) → 3.9–5.9GB（手机可用）
  • DeepSeek-V3.1 671B：671GB → 170GB（-80%）
  • GLM-5.2 744B 级：1.51TB → 约 217GB(1-bit) / 239GB(2-bit)，单台 Mac Studio 可跑
  • Hy3 295B MoE：混合 IQ1_M 约 1.75 bpw，1-bit 构建可塞进 MacBook Pro M3 Max 128GB
  • 腾讯 Hy-MT 翻译模型 1.8B：3.3GB FP16 → 440MB（-87%）

速度与能耗

微软的 bitnet.cpp 推理内核给出的数据很有代表性：x86 CPU 上速度提升 2.37–6.17 倍、能耗降低 71.9%–82.2%；ARM CPU 上速度提升 1.37–5.07 倍、能耗降低 55.4%–70.0%（bitnet.cpp 论文 arXiv:2410.16144；BitNet GitHub）。也就是说，越大的模型加速越明显，而能耗几乎是"腰斩再腰斩"。

性能保留

这里要诚实：不同路线差异明显。

  • 原生模型（BitNet、Falcon3）：同尺寸下接近 FP16。
  • Bonsai Ternary 版：约 95%；1-bit 版：约 90%。
  • Unsloth Dynamic：多数任务仍具竞争力，其 1-bit DeepSeek-V3.1 在 Aider Polyglot 编程基准上甚至超过了 GPT-4.1(2025.4)、GPT-4.5（Unsloth Dynamic GGUFs on Aider Polyglot）。
  • 混合精度 PTQ（如 Hy3 IQ1_M）：即便整体压到约 1.75 bpw，295B MoE 仍能输出连贯、语法正确、推理结构清晰的结果，说明"敏感层保护"策略对超大模型尤其有效（AngelSlim/Hy3-GGUF 实测）。
  • OneBit 这类早期 1-bit QAT 框架：约保留 83% 非量化性能（arXiv:2402.11295）。

结论：1.58-bit ternary 是当前"性能/体积"平衡的甜点区。纯 1-bit binary 更极端，适合对体积极度敏感、能接受轻微性能下降的场景。

六、部署框架怎么选

选对框架和选对模型同样重要。

bitnet.cpp（微软）

专为原生 1.58-bit 模型设计的推理内核，是 BitNet、Falcon3 的最佳搭档。如果你用的是原生 ternary 模型，这是首选（BitNet GitHub）。

llama.cpp（IQ1_M / TQ1_0 / UD-IQ1）

最通用的 PTQ 方案，几乎支持所有模型。它的 I-Quant（IQ 系列）用查找表换取内存效率，适合把主流开源模型压到极低比特跑在消费级硬件上。想深入了解各种推理框架的取舍，可以看我们的LLM 推理框架选型对比。

MLX / MLX-Swift（Apple）

Apple Silicon 设备的最佳选择。Bonsai 27B 就是通过 MLX Swift 在 iPhone 上跑起来的。如果你的目标是 Mac 或 iPhone，MLX 的原生优化会带来明显优势。

Axolotl + onebitllm

如果你想自己微调一个 ternary 模型，这是 TII 推荐的训练框架组合（用 Axolotl 训练低比特 ternary 模型）。

一个简单的选型决策树：

  • 用原生 BitNet/Falcon3 → bitnet.cpp
  • 压缩现有开源模型 / MoE 大模型 → llama.cpp + Unsloth Dynamic GGUF
  • 目标是 Apple 设备 → MLX
  • 要自己训练 ternary 模型 → Axolotl

关于私有化部署的完整实践，可以参考Xinference 私有化推理部署实践。

七、专用硬件：1-bit 的真正杀手锏

软件层面的加速终究受限于通用 CPU/GPU 不支持 ternary 运算。1-bit 量化真正的想象空间，在专用硬件。

学术界已经出现一批令人惊叹的原型：

  • VitaLLM：用台积电 16nm 工艺实现的 ternary LLM 加速器，解码吞吐 70.70 tokens/s，面积仅 0.223 mm²（比针尖大不了多少），功耗 65.97 mW，能效比（FOM）达 17.4 TOPS/mm²/W，大幅领先同类加速器（arXiv:2604.27396）。
  • TerEffic：FPGA 架构，全片上执行，速度超全精度基线 6.25 倍、超低比特基线 2.32 倍（arXiv:2502.16473）。
  • TeLLMe：首个在低功耗边缘 FPGA（如 AMD KV260）上完整支持 prefill + decode 的 ternary 加速器，7W 功耗预算下可达 9 tokens/s（arXiv:2504.16266）。
  • TOM（Ternary ROM）：最激进的思路——把 ternary 权重直接实例化为只读存储器里的组合逻辑电路，权重不是"存储再读取"，而是物理上就是电路结构，完全没有乘累加单元（arXiv:2602.20662）。

这些工作共同指向一个未来：当权重只有三个值时，硬件设计可以被彻底重构。这正是微软那篇论文里说的"为 1-bit LLM 设计专用硬件"的大门，如今正被一扇扇推开。

八、落地场景：1-bit 量化适合干什么

技术讲完了，回到最实际的问题——什么场景值得用 1-bit 量化？

手机本地 Agent

隐私敏感、需要离线、对延迟要求高的个人助理。Bonsai 27B 和腾讯 Hy-MT 已经证明这条路走得通。相关的端侧模型全景可以看2026 端侧大模型盘点。

离线隐私计算

医疗、法律、金融等数据不能出设备的场景。1-bit 让"在本地跑一个够用的大模型"成为可能，数据全程不出本地。

长上下文边缘推理

内存是长上下文的最大瓶颈。1-bit 权重 + 低比特 KV cache 能显著扩展在有限内存下可处理的上下文长度。想了解超长上下文的工程实践，可以参考长上下文 LLM 工作流指南。

可持续 AI（绿色计算）

能耗降低 5–12 倍，对大规模部署的电费和碳排放意义重大。当推理规模达到千万级请求时，这个差异是真金白银。

低成本本地服务器

预算迷你主机（如 Intel N100/N305）纯 CPU 就能跑 BitNet 2B4T，5–10 tokens/s，足够做一个私有的低功耗助理（BitNet on Mini PC）。

不太适合的场景：需要最高精度的复杂推理、代码生成的边界情况、对幻觉零容忍的生产环境——这些场景 1-bit 的性能损失可能不划算，建议至少用 4-bit 或更高。

九、趋势与展望

综合 2025–2026 的进展，几个明确的方向：

  1. 原生训练路线持续扩展。从微软 BitNet 单点突破，到 TII Falcon3 的完整产品线，原生 1.58-bit 模型正在形成生态。

  2. 动态 PTQ 成为最实用的落地方式。Unsloth Dynamic + llama.cpp IQ 系列的组合，让任何人都能把最新的开源大模型压到能在自己机器上跑——从 DeepSeek-V4、GLM-5.2 这样的千亿级 MoE，到 Hy3 的 295B，几乎第一时间就有 1-bit 量化档位可用，这是当前最接地气的路径。

  3. 混合精度 + 分组缩放成为高性能 1-bit 的标配技巧。纯粹的"一刀切"量化正在被"敏感层高精度、其余层极限压缩"的智能方案取代。

  4. 专用硬件是下一个爆发点。ternary 计算芯片、ROM 加速器一旦商用化，1-bit 模型的能效优势会被彻底释放。

  5. 更大规模的原生模型（70B+）与 sub-1-bit 探索。当原生训练能扩展到更大规模，配合 MTP 自推测解码，1-bit 大模型的能力边界还会继续上移。

小结

1-bit / 1.58-bit 量化在 2026 年已经从"论文里的疯狂想法"变成"手机里的可用产品"。核心要记住三件事：

  • 两条路线：原生训练（BitNet、Falcon3）性能最好但要从头训练；后训练量化（Bonsai、Unsloth）灵活实用能压现有模型。
  • 1.58-bit ternary 是甜点区：性能/体积平衡最好；纯 1-bit binary 更极端，适合体积极度敏感的场景。
  • 选型看目标设备：Apple 用 MLX，通用压缩用 llama.cpp + Unsloth，原生模型用 bitnet.cpp。

"手机跑 27B 大模型"已经不是标题党，而是 2026 年真实发生的事。对于想在边缘设备落地大模型的开发者，现在正是动手的好时机。
