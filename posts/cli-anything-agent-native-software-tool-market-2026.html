当软件的下一代用户是 AI：CLI-Anything 与 Agent 工具市场的未来

AI 工具生态 2026-07-13 · 21 分钟

45,200 颗 GitHub Star，4 个月，40+ 款专业软件获得了全新的 CLI 接口——不是给人类用的，而是给 AI Agent 用的。

这不是又一个 LLM Wrapper，也不是一个聊天机器人插件。CLI-Anything 正在做一件更底层的事情：重新定义软件的"用户"概念。当我们说"用户体验"时，那个用户可能不再是拿着鼠标的人类，而是运行在终端里的 AI Agent。

一、从一个问题说起：AI Agent 为什么操控不了真正的软件？

2026 年上半年，AI Agent 的能力边界已经从"写代码"扩展到了"用工具做事"。但一个尴尬的现实是——大多数 Agent 只能调用为它们专门设计的 API，面对 Blender、GIMP、LibreOffice 这些"人类的生产力工具"时，它们要么靠截屏+点击的 GUI Agent 路线（脆弱、慢、不准），要么就彻底无能为力。

这就是 CLI-Anything 试图解决的问题：

"Today's software serves humans. Tomorrow's users will be agents."

香港大学数据科学实验室（HKUDS）的研究者们提出了一个判断——与其让 Agent 学着像人类一样"看屏幕、点鼠标"，不如直接为 Agent 创造一套它们天生擅长的操作接口：结构化命令行。

二、CLI-Anything 是什么？

核心定位

CLI-Anything 是一个开源的 Agent-native CLI 生成器。它的核心能力是：

  • 输入：任何带有源码的软件（本地项目或 GitHub 仓库）
  • 输出：一套完整的、可安装的 Python CLI 包（Click 框架），Agent 可以通过命令行直接操控该软件的全部功能

一条命令 /cli-anything ./gimp，7 个阶段自动完成——从源码分析到测试通过到 PyPI 发布。

为什么是 CLI 而不是其他接口？

论文中明确阐述了选择 CLI 的六大理由：

  • 结构化 & 可组合：文本命令天然匹配 LLM 的输入输出格式
  • 轻量 & 通用：无依赖，跨平台，开箱即用
  • 自描述：--help 就是文档，Agent 可自动发现能力
  • 确定性：同样的命令产出同样的结果，可预测可复现
  • JSON 输出：--json flag 消除了解析复杂度
  • 经过验证：Claude Code 每天通过 CLI 运行数以千计的真实工作流

三、技术架构：7 阶段自动化流水线

CLI-Anything 的核心创新是一套完全自动化的 7 阶段管道：

阶段 1 - 分析（Analyze）：扫描源码，映射 GUI 操作到后端 API

阶段 2 - 设计（Design）：架构命令分组、状态模型、输出格式

阶段 3 - 实现（Implement）：用 Click 框架构建 CLI，支持 REPL 交互、JSON 输出、undo/redo

阶段 4 - 测试规划（Plan Tests）：生成 TEST.md，包含单元测试 + E2E 测试计划

阶段 5 - 编写测试（Write Tests）：实现完整测试套件

阶段 6 - 文档（Document）：更新 TEST.md 测试结果 + 生成 SKILL.md（AI 可发现的能力描述）

阶段 7 - 发布（Publish）：创建 setup.py，安装到 PATH

关键设计原则

  1. 真实软件集成：CLI 生成有效的项目文件，然后调用真正的应用程序渲染。Blender 真的用 bpy 渲染 3D 场景，LibreOffice 真的用 headless 模式导出 PDF。绝不用 Pillow 替代 GIMP，绝不做 toy implementation。

  2. 双模式交互：每个 CLI 既支持 stateful REPL（Agent 可交互式会话），也支持独立子命令（用于脚本和管道）。

  3. Agent-first 设计：所有命令内置 --json flag，Agent 获得结构化数据；同时保留人类可读的表格输出用于调试。

四、CLI-Hub：Agent 工具的"应用商店"

如果说 CLI-Anything 是"生成器"，那 CLI-Hub 就是它的"分发市场"。

pip install cli-anything-hub
cli-hub list          # 浏览注册表
cli-hub search image  # 按关键词搜索
cli-hub install gimp  # 一键安装
cli-hub launch gimp   # 启动使用

更重要的是，CLI-Hub 提供了一个 meta-skill，让 Agent 可以自主发现和安装需要的工具：

npx skills add HKUDS/CLI-Anything --skill cli-hub-meta-skill -g -y

安装后，Agent 只需要一句 prompt：

"Find appropriate CLI software in CLI-Hub and complete the task: ..."

Agent 就会自动去 CLI-Hub 目录搜索合适的 CLI，安装它，阅读它的 SKILL.md 了解用法，然后完成任务。这形成了一个完整的 Agent 自主工具发现 → 安装 → 使用闭环。

六、CLI vs MCP：Agent 工具接口的两条路线

2026 年 Agent 工具生态中最热门的争论之一是：CLI 还是 MCP（Model Context Protocol）？

维度 CLI MCP
连接模型 无状态，每次调用启动进程 有状态，持久化会话
类型系统 弱（文本 + JSON） 强（typed sessions）
部署复杂度 极低（pip install 即可） 中等（需要运行 server）
人机通用性 高（人类也用 CLI） 低（专为 Agent 设计）
生态成熟度 极高（30+ 年积累） 新兴（2024年开源）
适用场景 本地开发、快速迭代 企业集成、多用户系统

CLI-Anything 的判断是：CLI 已有 30 年的生态积累——git、docker、kubectl、aws cli——这些工具已经经过数百万人的检验。Agent 本质上就是"一个高级 shell 用户"，让它用人类已经验证过的接口，比为它重新发明一套新协议更务实。

但这并非非此即彼。论文 arXiv:2606.24551 的研究表明，GUI Agent 和 CLI Agent 面临不同的执行瓶颈：

  • GUI Agent 瓶颈在"长序列操作中的可靠视觉定位"
  • CLI Agent 瓶颈在"skill 接口的覆盖性和可扩展性"

CLI-Anything 通过自动化生成 + 社区贡献 + /refine 迭代，正是在解决 CLI 路线的核心瓶颈。

八、对开发者和企业的实际影响

对独立开发者

如果你维护一个开源工具，现在只需要一条命令就能让它进入 Agent 生态：

/cli-anything ./your-project

生成的 CLI 自动获得 SKILL.md、CLI-Hub 注册资格、和所有 SKILL 兼容 Agent 的发现能力。这相当于为你的项目打开了一个全新的"Agent 用户"渠道。

对企业

内部工具 Agent 化不再需要从零开发 API：

  1. 指向内部工具的源码
  2. 自动生成 CLI harness
  3. 通过 SKILL.md 集成到企业 Agent 工作流

对 AI Agent 开发者

不再需要为每个软件单独写 tool wrapper：

# 过去：为每个软件手写 tool
def use_gimp(prompt): ...
def use_blender(prompt): ...

# 现在：所有 CLI-Anything 生成的工具用同一模式调用
subprocess.run(["cli-anything-gimp", "--json", "project", "new", ...])

九、局限性与挑战

任何技术都不是银弹，CLI-Anything 目前面临的主要挑战：

  1. 依赖强模型：稳定生成高质量 CLI 需要 Claude Opus 4.6 或 GPT-5.4 级别的 foundation model。使用较弱模型可能产出不完整的 harness。

  2. 源码依赖：项目依赖可读的源代码。面对闭源商业软件（只有编译后的二进制），生成质量会显著下降。

  3. 覆盖率迭代：单次 /cli-anything 不一定能覆盖软件的全部功能。通常需要多次 /refine 才能达到生产质量。

  4. CLI 路线的固有瓶颈：相比 MCP 的有状态会话，CLI 的无状态模型在需要复杂上下文管理的场景下可能力不从心。

  5. 安全性：社区贡献的 harness 质量和安全性参差不齐（虽然项目已有安全加固措施，如 defusedxml 解析、路径遍历防护等）。

十、展望：Agent 工具市场的未来

CLI-Anything 代表的不仅是一个工具，更是一种范式转变：

短期（2026 下半年）：CLI-Hub 继续扩展覆盖面，预期 100+ CLI 进入注册表。与 MCP 生态互补而非替代——CLI 做本地快速调用，MCP 做云端企业集成。

中期（2027）：Agent 工具市场标准化。类似 npm 之于 JavaScript，CLI-Hub + MCP Hubs 可能成为 Agent 工具的主要分发渠道。质量和安全认证体系会逐步建立。

长期：当软件的"Agent 接口"变成标配，新软件可能从设计之初就同时考虑"人类用户体验"和"Agent 用户体验"——这将从根本上改变软件架构的设计范式。

正如 CLI-Anything 的 slogan 所说的那样：今天的软件服务于人类，但明天的用户将会是 Agent。这个"明天"，比我们想象的来得更快。
